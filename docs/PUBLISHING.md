# Публикация без утечки контекста

Перед созданием публичного GitHub-репозитория выполните независимую проверку:

1. Сканируйте дерево на персональные данные, имена клиентов, private URLs,
   токены, пути, историю операций и commit metadata.
2. Убедитесь, что fixtures и runtime-конфиги не содержат реальных сетевых
   endpoints, ключей, исполняемых файлов, установщиков, архивов и root CI
   workflow. Документальные ссылки на первичные источники в `docs/SOURCES.md`
   допустимы, если они не являются конфигурацией или исполняемой инструкцией.
3. Проверьте, что `LICENSE` содержит выбранную Apache-2.0, а author/committer
   используют verified GitHub noreply address владельца публичного аккаунта.
4. Создайте **новую** историю Git из проверенного дерева; не публикуйте рабочую
   локальную историю и не копируйте hidden `.git`.
5. Независимый reviewer подтверждает, что fixtures остаются инертными и README
   не обещает защиту, которую сканер не реализует.

Публикация, push, PR и включение CI — отдельные внешние действия и требуют
явного решения владельца.
