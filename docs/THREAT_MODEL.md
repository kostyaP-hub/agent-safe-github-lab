# Модель угроз: что проверяем до допуска

Внешний контент — данные, а не инструкция. В том числе README, issue, workflow,
package manifest и команда из документации. Их статический разбор позволяет
принять решение о следующем безопасном шаге, но не разрешает выполнение.

| Сигнал | Почему важен | Безопасный следующий шаг |
| --- | --- | --- |
| Prompt injection | Текст пытается сменить цель, обойти правила или выпросить секрет. | Остановить автоматизацию, сохранить минимальный receipt, запросить проверку. |
| `curl`/`wget` → интерпретатор | Код появляется после начальной проверки и сразу исполняется. | Не запускать; зафиксировать URL и цель, допускать лишь отдельным изолированным процессом. |
| URL + доступ к переменной окружения | Возможная эксфильтрация токена, конфигурации или данных. | Отключить сеть и секреты; не включать значение секрета в receipt. |
| Ветка, тег или `latest` вместо immutable SHA | Проверенный сегодня объект может измениться завтра. | Зафиксировать commit digest; повторить допуск при изменении. |
| Lifecycle script | Установка пакета может стать исполнением кода. | Не устанавливать автоматически; проверить manifest и изолировать запуск. |
| Privileged CI / broad permissions | Код workflow может получить токены, write-доступ или доступ к runner. | Минимизировать token permissions, пинить action по полному SHA, не давать секреты недоверенному коду. |
| Submodule, LFS-подобная ссылка или build backend | Проверяемое дерево указывает на дополнительный код или объект за его пределами. | Сделать отдельный receipt для каждого нового источника до fetch/build. |
| Обфускация | Проверка не может надёжно понять фактический смысл скрытого кода. | Не декодировать и не запускать автоматически; запросить отдельный review. |

## Изменение после «чистой» проверки

Проверка устаревает, когда меняются commit, подмодуль, package lock, URL,
разрешения CI, инструмент или политика агента. Такой триггер означает
**повторный допуск**, а не автоматическое продолжение.

Даже флаг `ignore-scripts` не превращает установку в безопасный процесс:
явная команда package manager или build backend может всё равно стать
исполнением. Политика должна запрещать автоматическую установку до отдельного
допуска, а не полагаться на один флаг.

## Что receipt сознательно не доказывает

Лаборатория не читает `.git`, поэтому digest описывает только прочитанные
обычные файлы, а не commit provenance, все permissions или исключённые объекты.
Она также не защищает от изменения дерева во время обхода. В реальном процессе
сначала фиксируют upstream commit/asset digest в стабильном snapshot, затем
выполняют ограниченную статическую проверку, и только после явного допуска —
изолированное выполнение с отключёнными секретами и egress по умолчанию.

## Ограничение лаборатории

Фикстуры — не вредоносное ПО и не тест на обход защиты. В них нет работающего
payload, реального домена, настоящего секрета, исполняемого файла или workflow,
который запускается в корне репозитория. Они предназначены только для чтения и
статического сканирования. Файл `model.pointer.inert` намеренно лишь похож на
LFS pointer: это не объект, который должен обрабатывать Git LFS.
